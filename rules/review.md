# Review

- **Parallel reviewers.**
  - When a task is finished, review the whole change before committing or merging it.
  - Run the reviewers in parallel, each as its own agent.
  - Simplicity: the smallest change that fully solves the task.
  - Design: stress-test the decisions behind the change.
  - Stack: one reviewer per technology, checked against its current docs.
  - Security: a focused review of the change.
  - Tests: every behavior change has a test that fails when it breaks, and the full suite passes.
  - UI: a design critique and audit, skipped only when no UI changed.
  - Today these run as: `ponytail`, `grilling`, `ctx7` docs, `security-audit`, `impeccable`.
  - Check it: every reviewer has reported before the merge.
- **Review rounds.**
  - Repeat review rounds until a round finds no defect.
  - Rounds 1 and 2 review the whole branch.
  - From round 3, re-run only the reviews that had findings, on the commits since the last round.
  - From round 3, only defects count: wrong behavior, a crash, lost data, a store rejection, a broken rule.
  - Fix wording and style findings when they're cheap; they don't call for another round.
  - If round 4 still finds defects, stop and ask the owner: the change likely needs a decision.
  - Finish the rounds before merging, even when the work runs long.
  - Cut the rounds short only when the owner says so.
- **Close every finding.**
  - Fix every review finding, or record why it stands.
  - Fix clear defects in the same change.
  - A finding that needs a decision becomes an issue, and the work moves on.
  - After fixing, re-run each reviewer whose area the fixes touched.
  - Check it: every finding is marked fixed, recorded or filed.
- **Reviewers only read.**
  - Reviewers read the change; they never edit, commit or switch branches.
  - Reviewers don't start agents of their own.
  - Each finding gives the file, the line, what goes wrong and a fix.
  - Findings come ranked, most serious first.
  - Why: a reviewer that moves the branch can break another session working in the same checkout.
