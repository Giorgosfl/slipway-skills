# Develop

- **Gotchas file.**
  - Keep a gotchas file in the repo, grouped by area.
  - Add a line when a trap costs real time.
  - Each line names the trap and its issue number.
  - Longer detail goes in a separate file for that area.
  - Remove a line once it is no longer true.
  - Read an area's section before working in that area.
- **Atomic.**
  - Every function, type, module and file has one responsibility.
  - Each has one reason to change.
  - A file that mixes concerns, such as routing, data and rendering, gets split.
  - A unit past about 150 lines is a signal to extract.
- **Clean code.**
  - Names say what a thing is or does.
  - Delete dead code.
  - Split a function instead of giving it a boolean flag that switches its behavior.
  - Write code plain enough to read without a comment explaining it.
- **DRY.**
  - The same logic, markup or styling written twice becomes one shared piece.
- **KISS.**
  - Make the smallest change that works.
  - Make it in the one place every caller goes through, not in each caller.
  - Use the platform's built-in feature before writing your own.
  - Use an installed dependency before adding a new one.
  - Use a plain function before a class or a factory.
- **SOLID.**
  - Add a feature by adding a new module, not a new mode to an existing one.
  - Depend on another module's small public interface, never on its internals.
  - The app's entry point only wires modules together.
  - Each module owns its own state.
- **Validate at boundaries.**
  - Data coming from outside is checked by a schema, once, where it enters.
  - Outside means forms, API and IPC calls, files, stored data, URLs and external services.
  - Use the schema instead of scattered type checks.
  - Read stored data leniently: a bad field falls back to its default on its own.
  - Read API and IPC input strictly: a bad field rejects the whole call.
- **Constants.**
  - User-facing text, limits, storage keys and routes each live in their own constants file.
  - A user-facing string or number written inline in the code is a bug.
  - Developer log messages stay inline.
